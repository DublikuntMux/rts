# M3 implementation contract

This document fixes the shared interfaces while the protocol, relay and client are built.

- `rts_net` depends on base, serde, RON and thiserror. Wire messages are RON text, protocol version 1. No renderer or socket dependency in the protocol.
- `MatchSetup { rules: String, map: String, seed: u64, players: u8 }` stores original RON content. `checksum() -> u64` includes content, seed, slot count and protocol version with explicit lengths; `simulation() -> Result<Sim, NetError>` validates content and exact map player count.
- `PlayerInput { player: PlayerId, commands: Vec<Command> }`.
- `Turn { tick: u32, inputs: Vec<PlayerInput> }`. `validate(expected_tick: u32, players: u8)` checks exactly one ascending input per player, bounds, and limits. `apply(&self, sim: &mut Sim) -> Result<(), NetError>` checks sequential tick and advances exactly once with supplied commands at that tick (no additional input delay).
- `ClientMessage`: `Create { version: u32, checksum: u64, players: u8 }`, `Join { version: u32, code: String, checksum: u64 }`, `Start`, `Input { tick: u32, commands: Vec<Command> }`, `Hash { tick: u32, hash: u64 }`, `Leave`.
- `ServerMessage`: `Lobby { code: String, player: PlayerId, players: u8, capacity: u8 }`, `Started { players: u8, input_delay: u32 }`, `Turn(Turn)`, `HashConfirmed { tick: u32, hash: u64 }`, `Ended { reason: String }`, `Error { message: String }`.
- Slot zero is host. Joining implies ready; only host starts a full room. Room codes are six uppercase alphanumeric characters. The relay authenticates the slot from the connection; clients never supply a player with an input.
- `PROTOCOL_VERSION = 1`, `INPUT_DELAY_TICKS = 2` re-exported from base, `MAX_MESSAGE_BYTES = 65536`, `MAX_COMMANDS_PER_TURN = 64`, `MAX_UNITS_PER_COMMAND = 1024`. Decode functions `decode_client(&str)`, `decode_server(&str)` enforce bounds; `encode_client(&ClientMessage)`, `encode_server(&ServerMessage)` return `Result<String, NetError>`.
- On start, the relay sends Started and empty Turn 1 (one empty input per player). Initial real submissions are for tick 2. Before advancing current tick `t` using agreed Turn `t+1`, each client sends pending local commands as Input `t+2`, including empty batches. It then applies the agreed turn and sends Hash for `t+1`. A missing turn stalls the simulation and retains pending local commands. There is no optimistic execution.
- Relay inputs must be sequential per connection, with no duplicate ticks, and a bounded lead over the next relay turn. Turns are emitted only when all slots submitted; ordering is ascending slot, then submission order inside the batch. Hash reports are sequential and bounded; differing hashes, an in-game disconnect, or a 15-second heartbeat/stall timeout ends the match for everyone. Pregame guest disconnect frees the slot; host departure closes the room.
- Replay `Replay { version: u32, setup: MatchSetup, turns: Vec<Turn>, final_hash: u64 }`. `Replay::new(setup)` validates setup and initializes hash from tick zero. `push(&mut self, turn: Turn, hash: u64)` validates continuity. `to_ron`, `from_ron`, `playback() -> Result<Sim, NetError>` reject invalid version, setup, turn order/players, oversized inputs, or a final hash mismatch. The client records every applied turn, offline and online, and can replay the latest recording without a socket.
- Networking: ewebsock 0.8 (default features disabled) in client, Tokio/tokio-tungstenite with TLS features disabled in the relay. Native uses `ws://`; the browser also supports `wss://` through its platform WebSocket. For TLS termination use a reverse proxy; native WSS is not enabled because the standard Rustls providers add C/assembly crypto dependencies. Document this limit; do not claim native WSS support.
- Server socket runtime is native-only. The server crate builds a no-network stub on wasm, while its protocol is cross-platform. All dependency versions are centralized in workspace.dependencies; crate deps use workspace inheritance.
